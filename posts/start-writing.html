为什么开始写东西，以及怎么不至于放弃

2026-10-09 · 约 4 分钟

我一开始写东西的理由很功利：想让人知道我懂什么。 后来这个理由很快就撑不住了——因为根本没人看。

真正让我写下去的，是把理由换掉之后。

写作是思考的验收环节

一个东西我「觉得」自己懂了，往往在写的时候才露馅。 讲不清为什么这样设计、说不出替代方案差在哪、举不出一个具体例子—— 这些都说明我只是记住了结论，没有真正理解它。

你以为自己懂了，直到你试着把它写下来。

所以我现在写的很多东西，本质上是写给三个月后的自己看的。 某个坑怎么绕过去的、当时为什么否掉了另一个方案、这段代码的边界条件在哪。 这些信息在半年后正好会忘光。

写什么：只写你刚解决的那个问题

最常见的毛病是想写「系统性的教程」。 一旦动了这个念头，就会先去看别人怎么写的，然后发现自己写得不如人家好，于是永远不发。

更实际的做法是：

  • 今天卡了两小时的报错，最后怎么定位的
  • 读完一篇文章，其中哪个结论和我的直觉相反
  • 做了一个小工具，为什么长成这样、放弃了什么

这类内容的共同点是只有你能写—— 因为它是你的经历，不是百度得到的知识。 这也顺带解决了「我写的东西是不是网上已经有了」的焦虑。

怎么坚持：把门槛降到可笑

我试过各种计划：每周一篇、每篇两千字、先列大纲。 全部失败了，因为它们都把「开始写」这件事变重了。

现在有效的做法有三条：

  1. 允许自己写得烂。先写完再改。中途修改的冲动是最大的敌人。
  2. 一次只写一节。状态好就写两节，不好就写一段，都算数。
  3. 不设发布周期。有东西就发，没有就不发。任务感会杀死兴趣。

另外，纯文本 + Git 这个组合意外地有用。 写作变成了一个可以 git diff 的过程， 改了什么、删了什么一目了然，也不会有「文档在哪儿来着」的问题。

公开写的好处，是意外的那部分

最直接的收益当然是有人读、有人来找你聊。 但对我更大的影响是：因为知道自己可能会公开，写的时候会更诚实。

如果只是私人笔记，很容易写下「大概就是这样吧」。 而一旦设想有陌生人会读到，就会逼自己把「大概」换成具体的版本号、具体的报错、具体的取舍。

至于没人看这件事，其实没那么重要。 我去年写的东西，读者最多的一个是我自己。

如果你也想开始

那就从今天遇到的那个问题写起。不用等有网站、不用等有主题、 不用等想清楚——写在任何地方都行，先写完一篇。

写完你就已经超过绝大多数打算写但没动手的人了。
