这个网站是怎么搭起来的，以及踩的三个坑

2026-10-24 · 约 6 分钟

在决定自己搭站之前，我试过三种方案：写在某平台的专栏里、用 Notion 公开页面、 以及干脆不写。三种都失败在同一个原因上——东西不在自己手里。

平台会改版，导出会丢格式，账号可能会因为莫名其妙的原因被限制。 我想要的东西很简单：一堆静态文件，一个域名，十年后还能原样打开。

为什么是 GitHub Pages

对比了一圈，结论是对于「纯文字 + 偶尔配图」的个人站，没有比它更省事的选择：

方案成本国内速度维护
GitHub Pages0一般push 即部署
云服务器 + Nginx几百/年快要管安全、证书、备份
静态托管（OSS/COS）几块/月快要备案

速度上它确实不是最优解，但「零成本 + 零运维」这一条对个人项目来说权重太高了。 真到了需要速度的那天，再迁也不迟——反正都是静态文件。

三步上线

  1. 建一个叫 用户名.github.io 的公开仓库。这个名字不能改，改了地址就变。
  2. 把 index.html 放在仓库根目录，push 上去。
  3. 仓库 Settings → Pages，分支选 main、目录选 / (root)，保存。
git init -b main
git add -A
git commit -m "init"
git remote add origin https://github.com/Tommy268/Tommy268.github.io.git
git push -u origin main

等一两分钟，https://tommy268.github.io 就能打开了。 从这一步开始，每次改完 git push，半分钟后线上就更新。

踩的三个坑

1. 名字写错，地址就变成了二级路径

如果仓库叫 my-site 而不是 用户名.github.io， 网站不是不能访问，而是会跑到 用户名.github.io/my-site/ 下面去。 这个差别很关键：一旦在子路径里，所有以 / 开头的绝对路径全部失效， 样式表、图片、页面链接会一起崩掉。

要么老老实实用根仓库名，要么把全站路径改成相对路径。 我选了前者，因为它顺带解决了「以后想绑自己域名时路径怎么算」的问题。

2. 文件名以 _ 开头会被静默吞掉

GitHub Pages 默认把仓库当 Jekyll 站点处理， 而 Jekyll 会跳过 _ 和 . 开头的文件。 结果是 push 成功了、Actions 显示部署成功、文件就是 404。

解决办法是在根目录放一个空的 .nojekyll 文件。 就一个空文件，什么都不用写，但少了它你会查一下午。

3. 改了不生效，八成是缓存

部署是真的要等，通常 20–60 秒。但更常见的误会是浏览器缓存： 尤其是 CSS 改完之后页面纹丝不动，很容易让人以为部署挂了。

养成习惯：改完 Ctrl + F5 硬刷新，或者开一个无痕窗口看。 另外去仓库的 Actions 标签页能看到每次部署的真实状态， 比盯着页面猜要快得多。

几个事后觉得值得的决定

  • 不用框架。总共四个页面，手写 HTML 比装一套构建工具快。
  • 不用 CDN。一个本地 style.css 就够，少一个外部依赖就少一个挂掉的点。
  • 加 prefers-color-scheme。十几行 CSS 就能支持深色模式，体验提升明显。
  • 正文用 rem 和相对行高。手机上读长文章舒服很多。
能在十分钟内上线的东西，才有机会被真的上线。

下一步要做的是绑自己的域名，还有给文章加评论。 不过说实话，先写十篇再说这些也不迟。
