我每天在用的 10 个 Git 命令

2026-10-18 · 约 5 分钟

Git 有几百个子命令，但真正每天敲的其实就十来个。 下面这些按使用频率排，都是我自己在用的版本，不是文档抄来的。

1. status —— 先看再动

很多人出问题的根源是一上来就 git add -A。 先看眼状态，成本几乎为零。

git status -sb

-sb 输出短格式，同时显示分支和领先/落后远端的提交数。

2. add -p —— 一次只提交一件事

改了三处不相关的代码，结果一个 commit 全塞进去了——以后 revert 的时候你会后悔。 -p 让你按代码块挑选要暂存的部分。

git add -p

交互里 y 收下、n 跳过、s 切更小的块、q 退出。

3. switch -c —— 开分支

老教程里的 checkout 一个命令干了太多事，新版把切分支拆出来了：

git switch -c fix/login-timeout
git switch main

命名我习惯用 类型/简短描述，看分支列表时一眼知道在干什么。

4. log --graph —— 看清历史形状

git log --oneline --graph --decorate -20

合并、变基之后历史会变复杂，把它画出来比读文字快得多。 嫌长就 git config --global alias.lg "log --oneline --graph --decorate"。

5. diff --staged —— 提交前最后一道关

git diff --staged

git diff 只看未暂存的改动，--staged 看的才是「这次提交到底包含什么」。 有没有把调试用的 print 带进去，全看这一步。

6. commit --amend —— 改掉上一条

git commit --amend --no-edit   # 只补文件，不改说明
git commit --amend             # 连说明一起改

⚠️ 只对还没 push 的提交用。推上去之后 amend 会改写历史， 队友拉取时会撞车。

7. rebase -i —— 整理提交

git rebase -i HEAD~3

把三条「wip」「再改一下」「真的能跑了」压成一条有意义的提交。 把 pick 改成 squash 即可合并，改成 reword 可以改说明。

原则：自己的分支随便改，公共分支别碰。

8. stash —— 临时中断

改到一半被叫去修紧急 bug：

git stash push -m "wip: 登录页"
git switch hotfix/xxx
# ... 处理完
git switch -
git stash pop

git stash list 看列表，stash pop 取回并删除， stash apply 取回但保留。

9. restore —— 后悔药

git restore file.py            # 丢弃工作区改动
git restore --staged file.py   # 取消暂存，改动保留

比记 git checkout -- 和 git reset HEAD 直观太多了。 注意第一条会真的丢掉未提交的改动，先确认 git diff 再敲。

10. worktree —— 同时开两个分支干活

这个用的人少但极好用。不用 stash、不用 clone 第二份仓库：

git worktree add ../hotfix hotfix/xxx
# 在 ../hotfix 目录里正常改，主目录保持不变
git worktree remove ../hotfix

线上出问题的时候，一边留着当前工作区，一边开一个干净目录去修，互不干扰。

外加两个救命命令

reflog —— 找回过的一切

git reflog

误删分支、reset 错了、rebase 搞砸了，只要提交过， reflog 里就还留着它的哈希，git switch -c rescue 哈希 就能捞回来。

bisect —— 定位是哪次引入的 bug

git bisect start
git bisect bad
git bisect good v1.2.0
# 二分测试，每次告诉它 good 或 bad
git bisect reset

一千个提交里找问题，手工翻要一天，二分法十几次就定位到。

小结

真正需要背下来的其实只有 status、diff、add、commit 四个， 剩下的都是出事时的工具。而所有工具里， 先把 reflog 记住，能省掉 90% 的心跳加速。
